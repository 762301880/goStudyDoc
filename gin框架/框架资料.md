###  **安装命令**

```shell
go get -u github.com/gin-gonic/gin

# 注意 需要对应go版本 如果go版本为go1.17.3    需要安装  go get github.com/gin-gonic/gin@v1.8.2
```

## 疑惑点解答

### gin为什么不是像laravel一样 目录分明 什么控制器 model 都给你规划的好好的  gin 就安装后啥都没有

原因其实很简单：

Laravel 和 Gin 的定位完全不一样

Laravel 是一个**完整的 Web Framework**，它非常强调「约定优于配置」。

你执行：

```php
laravel new xxx
```

它直接给你：

```php
app/
├── Console/
├── Exceptions/
├── Http/
│   ├── Controllers/
│   ├── Middleware/
│   └── Requests/
├── Models/
├── Providers/

database/
├── migrations/
├── seeders/
└── factories/

routes/
├── web.php
└── api.php

config/
resources/
storage/
tests/
```

甚至连 ORM、数据库迁移、验证、队列、缓存、认证等东西都给你安排好了。

**而 **Gin 本质上更接近一个 HTTP Web 框架 / 路由框架**。**

你：

```bash
go mod init my-project
```

然后：

```bash
go get github.com/gin-gonic/gin
```

Gin 的态度基本就是：

> “HTTP 服务我帮你搞定，剩下的你自己决定。”

所以你最后可能只有：

```go
my-project/
├── go.mod
├── go.sum
└── main.go
```

甚至：

```go
func main() {
    r := gin.Default()

    r.GET("/hello", func(c *gin.Context) {
        c.JSON(200, gin.H{
            "message": "hello",
        })
    })

    r.Run(":8080")
}
```

**这就是一个完整的 Gin 项目。**

**那为什么 Go 社区喜欢这样？**

这其实和 Go 的设计哲学有很大关系。

Laravel 更偏：

> **我给你一套标准答案，你按照我的方式开发。**

Gin 更偏：

> **我给你工具，你自己决定项目怎么组织。**

所以 Gin 并没有规定：

```php
controller
model
service
repository
request
resource
middleware
```

这些目录必须存在。

你完全可以：

```php
project/
├── main.go
├── user.go
└── db.go
```

也可以：

```bash
project/
├── cmd/
├── internal/
├── pkg/
├── configs/
├── migrations/
└── ...
```

甚至可以搞成：

```bash
project/
├── app/
│   ├── controller/
│   ├── service/
│   ├── model/
│   ├── repository/
│   └── middleware/
├── config/
├── router/
└── main.go
```
